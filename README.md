# Pilot Kit Box PCB 贴片助手

用于 Pilot Kit Box PCB 手工贴片的浏览器工具。选择板卡版本，对照 PCB 焊盘图和 BOM 信息找料、定位、贴装并记录进度，也可以在开工前按清单备料。

页面使用静态 HTML、JavaScript 和 JSON，不依赖后端服务，可在本机运行或部署到静态网站托管服务。

## 打开页面

在本项目根目录启动一个本地 HTTP 服务，例如：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

然后打开 <http://localhost:8000/>。

页面通过 `fetch` 加载板卡 JSON，需要通过 HTTP 或 HTTPS 访问。直接双击 `index.html` 可能被浏览器的本地文件跨源限制拦截。

页面默认使用中文。可在版本选择页、操作栏或打开的清单中选择 English；界面、BOM 说明与配料打印会随之切换。语言选择单独保存在本机浏览器的 `pk-assembly-language` 设置中，不影响已有贴片、备料或计时记录。

## 使用方法

1. 选择与实物一致的板卡版本和电源变体，阅读版本说明与贴装提醒。
2. 打开「备料」，按位号、规格、封装或型号搜索，逐组勾选已备好的料；可打印配料纸，按料位号摆放。
3. 开始贴片。顶部显示当前料的规格、封装、数量和 BOM 备注；板上高亮当前位号与同料位置，点击元件或右侧位号可定位。
4. 标记已贴或跳过缺料件，使用分类导航切换元件类别，打开「焊接表」逐项核对。

鼠标滚轮缩放、拖拽平移。正反面可切换；数据中带有极性信息的元件会显示阴极或 1 脚提示。换料时弹出换料卡，提示这种料还需贴装的数量。

| 快捷键 | 作用 |
|---|---|
| 空格 | 标记当前件已贴并前进 |
| Enter / A | 将当前组剩余元件标记已贴，进入下一组 |
| Z | 撤销上一次批量标记 |
| ← / Backspace | 退回上一个，同时取消它的已贴标记 |
| → | 前进，不标记 |
| S | 跳过当前件，不计入已贴 |
| P | 打开或关闭备料清单 |
| Tab | 打开或关闭焊接表 |
| F | 切换正反面 |
| 0 | 复位缩放和平移 |
| Esc | 关闭清单 |

备料清单中的空格用于切换当前组的备料勾选并前进，方向键在搜索结果中移动。备料勾选与贴片进度分别记录。

页面还记录操作间隔估算的活跃贴片时间，以及各组耗时；超过五分钟的操作间隔不计入。底栏「重贴」与焊接表「全部清空」会清空贴片进度和计时；「清空备料」只清除备料勾选。

## 进度与个人数据

已贴、跳过、备料勾选和计时保存在本机浏览器的 `localStorage` 中，按板卡版本区分。关闭后重新访问相同站点可以继续；更换浏览器、设备、访问地址或清除站点数据后，不会自动带入原进度。页面不提供账号或云端同步。

可选的 `data/batches.json` 用于显示个人采购批次；缺少它时其余功能照常使用。个人批次数据仅限本地，不应纳入版本控制或站点发布；仓库已配置相应的 Git 忽略规则。

## 数据结构与维护

- `index.html`：页面、交互与 PCB 图形渲染。
- `i18n-en.js`：版本目录与 BOM 中文显示字段的英文词典。
- `data/index.json`：版本目录，包含每版的 `id`、标题、说明、位号总数和料组数量。
- `data/<id>.json`：对应版本的完整数据，包含板框、元件分组、BOM 参数、位号、正反面、坐标、焊盘轮廓及极性信息。

页面按版本 `id` 加载同名 JSON。新增或更新板卡时，应同时核对索引、版本文件、数量和版本说明，确保几何、BOM 与实物版本一致，并为新增或修改的中文标题、说明及 BOM 显示字段补齐 `i18n-en.js` 英文词条；各历史版本保留自身的贴装规则。

板卡数据由 [Pilot Kit Box 硬件工程](https://github.com/naizhao/Pilot-Kit-Box-ESP32-P4) 中的生成工具从对应 PCB 和 BOM 整理。PCB 几何变化后应重新生成对应数据，不能用旧渲染图片代替焊盘坐标；BOM 或选贴规则变化后也应同步更新。页脚显示数据中的源 PCB 日期，便于核对。

维护页面与数据时，请检查位号定位、正反面、极性、同料分组、数量及选贴范围。公开内容仅保留装配所需的技术信息，不包含个人采购记录、库存信息或内部工程资料。

页面、数据和发布脚本在本仓库根目录直接维护。硬件工程生成对应 JSON 后，将索引和版本数据更新到 `data/`，再执行：

```sh
python3 scripts/export_site.py --prepare
python3 -m unittest discover -s tests -v
python3 scripts/export_site.py --publish
```

`--prepare` 先校验全部公开数据，再定向去除 note 中的个人采购记录。`--publish` 校验目标仓库与空暂存区，精确提交公开文件并推送 main；只应在准备正式发布时执行。Pages 从本仓库已提交内容打包，产物 `_build.json` 记录本仓库提交 SHA。切换域名或访问地址会改变 localStorage 的存储空间，原地址的贴片进度不会自动迁移。
